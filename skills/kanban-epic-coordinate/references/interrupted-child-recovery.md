# Interrupted child recovery

Correlate each notification to its actual process handle, assigned phase and session; a running process after a wait timeout is still pending. Distinguish launch, exit, individual mutation receipts, gate results and acceptance. An exit code alone cannot turn an explicit incomplete result into a pass.

Snapshot current source, branch, index, untracked owned paths and card stage. Preserve unrelated opaque paths; separate coordinator-staged moves from executor changes. A rejected patch says only that the rejected invocation did not land; retain earlier verified edits. Record each actual check's native exit and evidence, rather than inferring success from a later command.

Classify the interruption: runtime ceiling, incomplete evidence capture, patch-context mismatch, native access/security denial, or real gate/review failure. Preserve authentic partial receipts. Continue the same authorized scope and missing proof using the available runner; do not duplicate an active process or manufacture historical evidence. A true owner-imposed invocation limit governs its exact operation; ordinary process timeouts are not such a limit. Never bypass a native security denial by changing tools or routing.

Record landed edits, stale and current evidence, incomplete gates, source pins and the exact next phase. For owned integration fixtures, verify the actual test resource and revision before cleanup or restart; do not touch foreign resources or guess a migration state. Finish authorized phases in their specified order, perform required fresh acceptance against the actual candidate, and verify final card, index and any authorized commit. Prior failures remain historical failures.

For durable state-machine recovery, verify symmetric fenced mutations and rejection behavior, use real persistence tests for durability and restart claims, and keep external effects within their owning leased or journaled step. A simulated interaction alone does not prove durable recovery.

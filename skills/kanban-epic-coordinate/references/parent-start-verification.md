# Parent start verification

Confirm the canonical parent, children, branch and baseline; record the approved next child, dependency sequence, parked grooming gates, evidence plan and action boundaries. Preserve historical decisions and use a compact matrix where useful. Parent start does not itself authorize child work, merge, push or deployment.

Run relevant targeted lint and diff checks; move only the authorized parent through the board's canonical helper. Re-read the destination, reconcile any status field that the format maintains, and preserve unrelated children and allocation state. If a commit is authorized, explicitly stage the final parent body and inspect the path set and repository message policy; verify committed content, post-change checks and remaining worktree state.

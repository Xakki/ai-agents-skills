# Configuration defaults and rollout verification

Define the ownership, explicit override and runtime scope of each setting. Compare applicable source defaults, environment precedence, deployment overlays, generated artifacts, request options and actual consuming process. Empty environment interpolation can override another source; verify the true precedence rather than guessing. A changed default does not retroactively change a running process or persisted job. For budgets, establish the actual counted quantity, owner, clock and retry aggregation; request-time limits, context capacity and transport support are distinct.

Test absent, explicit valid, false or empty where applicable, malformed and unrelated-scope controls. Trace real forwarding and enforcement rather than only a parsed value. For multi-stage systems, include every dispatch and continuation path before claiming a global limit. Preserve caller-selected overrides and do not infer a default value from an unrelated example.

Validate effective configuration with approved tools while ensuring rendered secrets never enter output. Static semantic validation must be labeled as such; it does not replace a native parser, startup or live deployment check. For structured documents, honor the actual format contract when detecting duplicates, aliases, merge keys, recursive structures and nested sensitive references. Keep input values unchanged when a read-only review encounters invalid state.

When aliases or sentinel values are supported, test the complete producer-to-consumer identity and serialization path. An explicit null can mean something different from an absent field or invalid reference; canonicalizing a name in one layer does not prove that caches, generated catalogs and runtime selectors use the same identity. Preserve accepted legacy aliases only as the actual compatibility contract requires.

Where a versioned external capability manifest is an authority, bind its full provider identity and version, not a suffix or similarly named identifier. Validate configured entries against the declared verified set, while preserving the documented behavior for other providers and absent declarations. Distinguish available-at-runtime discovery from the authorized static contract; probing a service is not evidence that a configuration is permitted. Treat health as capability-specific where the product contract requires it, and do not substitute an unrelated default when an explicit route must remain authoritative.

Compare generated catalogs and consumer views with the canonical inputs without mutating the working tree during a review. Use sanctioned generators only for authorized changes that require regeneration. Record focused and broader checks separately, identify reload/restart requirements and unverified environments, and report actual failures rather than a synthetic pass.

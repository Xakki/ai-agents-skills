# Documentation research

Use when the task asks for a source-grounded contract or comparison from documentation. Identify the question, source classes, date, permitted inputs and requested output before retrieval. When scope is documentation-only, do not fetch actual records, feed entries, samples or live APIs; a documented example is not proof of runtime compatibility.

Find authoritative current documentation for the relevant service and version. Search snippets help discover sources but do not establish detailed claims; read the actual page or specification when available. Record direct citations for documented facts, version or date, explicit limits and unanswered questions. Separate documented behavior, inference and live verification, and distinguish access terms and authentication from implied permission to use the data.

For API contracts, compare relevant endpoints, methods, authentication, request/response shapes, pagination, errors and streaming only where supported by sources. For source-landscape decisions, describe population, identifiers, geography, time, access and limitations needed by the actual question. Do not fill gaps with invented endpoints, values or a blanket recommendation.

A proposed source, working endpoint or accepted research design does not itself authorize publication, processing real records or sending messages. Use available retrieval interfaces and the citation format applicable to the requesting runtime. For edits to existing API documentation use [API documentation](../api-documentation/SKILL.md).

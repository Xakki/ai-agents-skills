# Merge and parent review

Resolve the exact source and target refs, merge bases, intended scope, current checkout, index and approved recovery boundary before integration. Tree differences between two tips are not by themselves incoming deletions or proof of a conflict. Inspect relevant paths in each merge base and both tips, and confirm the proposed history does not carry unrelated work. Preserve adequate authorized recovery artifacts before any rewrite or destructive ref action; do not automatically copy secrets or bundles containing excluded material.

For authorized conflicts, compare the intention of each side and resolve by scoped hunk or explicitly chosen file; do not blindly choose a side for every conflict. Reconcile generated outputs from their canonical producers, then verify actual consumers. Avoid presenting a clean merge-tree preview as proof of accepted behavior or approved scope. Escalate a genuinely missing product or security decision, while applying existing grants without repeatedly asking about mechanical choices.

For read-only merge acceptance, freeze merge and parent SHAs, reviewed scope and status. Compare each important conflicted path against both parents, check compatible contracts, symbols, schemas and tests, and run the relevant authorized focused checks. Inspect actual unmerged paths and conflict-marker context rather than treating every line of equals signs in legitimate documentation or fixtures as a conflict. Marker-free and lint-green do not prove both parents' behavior survived. Report concrete findings, scope, current results, environment limits and minimal repair. Do not mutate as part of read-only review.

# Branch history and retirement

Resolve authoritative source, target, current branch, other worktrees and full tip IDs. Compare ancestry, parent ranges, complete content and relevant accepted checkpoints separately: ancestry, patch equivalence, a merged PR and source inclusion answer different questions. A branch is not completed merely because a card or branch name says so. Squash and cherry-pick integration require additional evidence; absence of unique commits alone does not account for uncommitted or ignored work in an attached worktree.

Before an authorized history rewrite, ref deletion or force update, preserve an adequate recoverable baseline for each intended source under the task's privacy and authorization boundary. Check requested blocks, parentage, added and deleted files, actual resulting tree and approved exclusions. Compare the new candidate to the preserved source, run required gates and independently review where required. Do not invent a branch naming scheme, repository-specific trailer, bundle containing secrets or fixed commit count.

For a requested bounded-history reconstruction, pin the intended baseline and source range, group the admitted commits according to the user's chosen boundaries, and verify each resulting commit and the final tree against the preserved source. Applying commits without committing can leave newly added files untracked after a mixed reset; inventory and stage admitted new files as well as modified tracked files, rather than assuming a tracked-only diff contains the complete result. Enumerate and obtain acceptance for any intentional tree difference. Local rewrite authority does not imply a remote push or forced update.

For branch rename, verify the new ref and current checkout independently; renaming a non-current branch does not switch the checkout. Never merge into an assumed branch without verifying it. For cleanup, list linked worktrees, uncommitted state and in-progress merges; retain refs or worktrees with unaccounted work. Verify candidate-to-keeper ancestry in the correct direction and recheck tips immediately before an authorized deletion. Preserve full recovery identities and distinguish local deletion, remote publication and remote deletion. A checked-out branch must not be removed by deleting a dirty worktree. Confirm the actual remote and read back separately authorized remote changes.

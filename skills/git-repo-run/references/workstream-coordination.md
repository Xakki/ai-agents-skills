# Multiple workstreams and shared checkouts

Resolve the approved commit scope, ordering, number of commits, branch, worktree and allowed path set before staging. An explicitly authorized all-current checkpoint may include unrelated work, but not secrets, excluded opaque content or unclassified files by default. Separate lifecycle mutations, product work and independent debt according to the requested schedule, without inventing commits or mandatory trailers.

Concurrent read-only discovery can share a checkout; serialize index/ref mutations and conflicting writers. A whole-tree analyzer can consume other actors' changes even when path ownership differs. If concurrent unrelated changes are explicitly allowed, freeze a complete permitted source/test candidate including new files and required absences, run gates against that actual snapshot and bind receipts to it. A launch result, status message or timeout does not establish that a process stopped or a gate passed.

Refresh the current actor's baseline when its phase begins; preserve pre-existing staged and working changes. Stage only admitted paths and hunks, with tracked removals and both rename endpoints accounted for. If one path spans workstreams, verify the selected patch and every intermediate commit's own tests and dependencies. Preserve partial landed edits after a later patch failure. A committed subset is not evidence that a requested combined candidate passed.

At handoff verify actual branch, parent, commit path membership and bytes, message policy, native results, remaining owned scope and protected state. Distinguish acceptance from checkpoints, gate failures, unavailable evidence and future integration. Only claim globally clean when independently observed.

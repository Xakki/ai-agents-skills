# Autonomous pool checklist

Before each card, confirm its canonical scope, dependencies and actual stage, and reconcile possible completed copies or existing task branches. Record unrelated dirty and staged state and identify safe project test targets and shared-state boundaries. Check actual helper effects; a filesystem move may be an unstaged deletion plus an untracked destination, not a staged rename.

For a deferred-review pool, determine each allowed stage from current project entry gates before dispatch. State pending gates and do not direct a premature forward move. Run focused tests for the owned change, and required broad checks and independent review on the final combined candidate.

If an executor stops, verify it exited and capture HEAD, index, owned changes, protected paths, last native result and remaining gates. Resume its continuity session where available with only the missing authorized phase; preserve partial work and do not discard it. A native security veto stops the denied operation. Keep unrelated work untouched and do not advance while the partial state is ambiguous.

Ask a reviewer to compare acceptance with actual source, call paths, persistence, affected public contracts, required test matrix, lifecycle and evidence. For mutable data, record the actual source, scope, time and observed result as a point-in-time observation.

# Queue and evidence

Inventory all requested items and relevant board stages. Inspect canonical current cards, legacy identifiers, existing completed work, dependencies and applicable source contracts. Classify each item as new work, merge into a canonical card, existing-card repair, bounded follow-up, historical context or authorized retirement; preserve every unique acceptance criterion. A request to explain a scratch note is an audit, not authority to delete or allocate. Reconcile the final disposition set against the requested queue before claiming completion.

For scope derived from a catalog, state the selection predicate over its authoritative row fields and assignments, then separately account for unassigned, unsupported, excluded and missing entries. Recompute every matching current row and representative cross-category cases instead of assuming a target file type determines the execution mode. Preserve special-route contracts and leave genuinely unknown inventory unresolved.

When the owner asks to approve a plan before card creation, present the scoped decomposition, dependencies and decisions first. For an explicitly delegated choice, choose only within that grant and record rationale and boundaries. When approval is required, explain each independently decidable material choice, consequences, alternatives and recommendation; an empty response or timeout is not approval. Record the exact answer and reconcile current claims in affected cards before the next question. Respect explicit per-card advancement gates without reopening settled decisions.

For an operational decision, specify the authoritative value and testable boundary, distinguish current from proposed configuration, and list ownership, verification, rollback and release gates that remain open. Static source, fixture results, prior logs and live observations are distinct evidence. Measurable performance cards must specify workload, units, window, sample count, aggregation and thresholds actually approved, rather than inventing targets.

Review changes against the authoritative source and approved decisions. Validate exact cards and board diagnostics separately, including zero-card or archived-stage exclusions; preserve frozen history and do not convert formatting repair into lifecycle or product authorization. Grooming alone does not implement or release the planned work.

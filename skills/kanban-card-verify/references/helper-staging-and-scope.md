# Helper effects and commit scope

Capture staged and working changes before and after board allocation or movement. A helper may change a lock or stage a card beyond the path it prints. Resolve the canonical board and indexed paths, including aliases; do not stage through a directory symlink. Separate owned implementation, task evidence and unrelated debt by authorized commit scope, preserving all foreign staged entries and working files. An operation-owned staged entry may be removed from the index only when the action is authorized and its working content is preserved; do not reset the whole index.

Discover the actual test tree and environment selected by each canonical target; a filter on a unit target does not imply functional tests ran. Run the applicable focused and board gates and check the actual cached diff. Record unrelated pre-existing failures precisely instead of claiming a full green gate or repairing unrelated cards. Refresh the destination card body after a mover stages a rename if evidence changed later.

For authorized separate product and lifecycle commits, verify exact source/destination paths and committed contents; Git may show a deletion and addition instead of a rename after substantial edits. Follow the actual repository policy for branches, messages and trailers. A `ready` state does not authorize `done`, integration or release.

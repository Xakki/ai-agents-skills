# Scope and safety

The local prototype uses a fixed-format scope manifest with a SHA-256 content identifier. It checks repository, branch and allowlisted card names. The manifest can be created by a caller supplying an approval flag, so it is not a signed user authorization or a substitute for verifying the actual request. Its current fixed permission set includes merge-at-ready: this is unsuitable for scheduling that does not expressly authorize that action.

The runner checks for tracked, staged and ordinary untracked changes before opening a window and rechecks immediately before agent execution. It serializes updated runner instances per repository, but it cannot coordinate other tools, older running instances or manual writes. Git checks and later mutations are not atomic. Ignored files are not inventoried by the clean-status check. Stop rather than infer ownership from filenames or a baseline set.

`park-task.sh <card> <base-branch> <baseline> <session> <log-dir> <reason>` checkpoints a card that cannot continue (reason: `qa-fail`, `review-fail`, `blocker`, `question`, `merge-conflict`). It works only inside an approved scheduled run (`SCHEDULE_SCOPE_ID` names a valid scope that lists the card and the base branch) and refuses an unmerged state, a merge/rebase in progress, a branch other than the base, or a non-empty run baseline (the run could not attribute changes). It commits the current working-tree changes to a new side branch `task/<card>` (or `-2`, `-3` if taken) from a throw-away index with plumbing only, verifies the commit and then writes `.parked/<card>` atomically. The current branch, the real index and every working-tree file stay as they were, no hooks run (this is a checkpoint, not a delivery commit), and nothing is switched, staged, stashed, reset or cleaned. The tree stays dirty, so the scheduler's clean-baseline checks stop the chain until an authorized step deals with the preserved work. That step is owner-run: `park-task-clean.sh [--repo DIR] (--branch task/<card> | --record <log-dir>/.parked/<card>)` prints a plan and `plan_sha256` (dry-run), and `--apply --plan-sha256 <hash>` then restores the checkout. It first proves that the branch is a single-parent `wip(park):` snapshot of the current HEAD, that every snapshotted path in the working tree equals the snapshot byte for byte (any later edit stops it) and that no path is staged differently; it then unstages those paths, restores modified and deleted ones from HEAD and unlinks the added ones, pruning only directories that become empty. Unrelated dirty files, the branch, the `.parked` record and every other ref stay as they are, and the parked changes stay recoverable with `git diff HEAD task/<card>`. It refuses to run inside a scheduled run (`SCHEDULE_SCOPE_ID` set) and is never offered to the agent. Do not chain, switch branches or notify as a consequence of parking or of a parking refusal. No automatic usage-stat staging or commit is performed. Ambiguous continuation jobs are not automatically cancelled because command-line matches do not establish job ownership. Report their state and leave cancellation to an explicitly authorized exact-job operation.

The prototype has no safe proof of every runtime interaction. A missing permission, reviewer, safe Git boundary or dependency blocks that action. Preserve failed results and state; do not bypass an agent's native approval controls, hooks or policy. See [Claude-specific mechanics](claude-runtime.md) only for that runtime.

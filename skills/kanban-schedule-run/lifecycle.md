# Lifecycle boundaries for scheduled work

A scope record is an exact ordered card allowlist bound to a repository and base branch. Check the actual user authorization against its complete operation set before creating it. A checksum detects changed bytes; it does not establish who approved them.

Verify stage entry criteria and existing decisions before acting. For every lifecycle transition use the project's actual sanctioned helper and verify physical destination, any maintained status fields and its effects on the index. Explicit user approval is required for `done`; merge, push, deploy, notification and each external effect are separate actions. Do not infer any grant from a card stage, credentials or a model verdict.

An independent review must actually be independent, bound to the candidate, and available before a required gate can pass. Stop and report when a reviewer or required input is missing. Do not manufacture a parked commit, move, recovery or success record to continue a chain.

Before any authorized commit inspect the whole index, including earlier entries, and preserve unrelated work. Staging exact paths does not exclude already staged files from a commit. The prototype refuses any dirty entry at start, but does not prevent unrelated writers after that check. If state changes unexpectedly, stop without branch changes, broad staging or reset. Report the last verified state and unrun work.

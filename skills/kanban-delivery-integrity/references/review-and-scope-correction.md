# Review and scope correction

When the user requires review before commit, give the independent reviewer the complete current candidate and required project-root gates. Repair confirmed in-scope defects and re-review within the actual authorized repair limit; do not commit or advance while its gate remains open. Preserve unrelated staged state and use exact paths for any separately authorized product or card commits. Verify the committed content matches reviewed bytes and report any remaining delta.

When work crossed into a downstream scope, compare the approved ownership matrix and inventory every affected family, including storage, route, schedule, tests and card claims. Correct only within the owner's authorized scope and retain the legitimate upstream contract; if no product implementation remains, say so. Prove the removed capability is absent at relevant discovery and integration seams rather than relying on unit tests alone. Any destructive test reset must target explicitly owned isolated resources and requires the applicable authorization; never reset development or production for convenience. Record a dated correction and preserve historical evidence.

For an explicitly authorized delivery of selected changes from an archival or blocked branch, compare exact source and target references and qualify the approved files and bytes before applying them. Preserve the source branch and unrelated work. Follow the authorized target branch and commit schedule; when product and board evidence belong in separate commits, verify their actual path sets do not overlap. Run the relevant product and board gates, qualify any unrelated baseline warnings separately, and verify the resulting card path, selected bytes and unchanged source reference. A branch name, historical trailer or a proposed stage sequence is not universal authority.

# Artifact acquisition, writes and bounded input

Identify whether the artifact is replaceable runtime state or immutable evidence; they require different replacement and cleanup rules. Define supported source/destination configuration and validate inputs before filesystem or network use. If the actual contract requires one canonical location, enforce that policy on every applicable CLI, environment and API entry; do not infer a fixed location for other projects. Keep test-only path injection clearly separated from production authority.

For sensitive reads and writes, obtain and retain an appropriately verified parent handle and no-follow file handle where the platform permits; check actual object type, identity, owner, mode, size and filesystem properties only as required. Path normalization followed by a fresh path open does not close replacement races. Bound the underlying read itself, not merely a later slice, and test read sizes at the handle. For a byte-limited text sample, specify strict decoding and behavior for an incomplete final multibyte character; do not accidentally truncate a full conversion that needs the whole input.

For durable replacement, use a private exclusive temporary object under the bound parent, validate and write bounded bytes, handle short writes, perform required file and directory sync, and replace atomically when supported. On failures preserve the documented final-state guarantee, close handles and clean only invocation-owned temporary objects. Validate any header/cookie or structured metadata at every real transport seam; reject unsafe controls and invalid types while preserving valid opaque values. Do not log payloads or credentials.

Test alternate paths, symlinks and parent replacement, disallowed types, bounds, malformed content, owner/mode where relevant, partial writes, replacement and independent file/directory sync failures. Include ordinary valid values, assert forbidden downstream operations never start on rejection and keep synthetic secrets out of outputs.

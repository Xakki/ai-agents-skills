# Credential selectors, replay and capabilities

When extending a credential-bearing selector, identify every existing caller and preserve its documented grant semantics. Distinguish absent, unrestricted and empty grants; do not conflate explicit registered credentials with default or ephemeral credentials or silently choose between ambiguous selectors. Require explicit opt-in where the new combination changes an existing contract. Deny unauthorized or foreign selectors before credential decryption, key spending and upstream work. Invalid ciphertext cannot be detected before reaching the credential layer; report ordering precisely.

Exercise the real handler, auth and storage seam with synthetic encrypted credentials and a stubbed upstream. Include owned permitted, foreign, unknown, disabled, missing-scope, malformed, ambiguous and missing-selector cases, plus established sibling paths. Assert the selected credential and fail-on-call sentinels for forbidden fallback. Compare actual persisted namespace and repeated requests rather than only derived owner strings.

For idempotent replay, authorize the current caller and all referenced resources before key lookup or result disclosure. Separate access entitlement from readiness to execute a new effect: a legitimately cached result may remain replayable when the original source bytes no longer exist, provided durable ownership evidence is sufficient; never start a new effect on that basis. Test callers sharing a replay namespace but holding different grants.

If the requested contract promises a one-time bearer download, use an opaque high-entropy token and documented TTL; consume it atomically before opening or streaming the resource. A signed expiring URL alone remains replayable. Keep the capability consumed after downstream failure, and use the established indistinguishable denial and no-store response policy for both success and failure. Exercise first, repeated, concurrent, expired and malformed requests at the real state-store/HTTP seam. Apply this contract only where one-time semantics are required.

# Lease fencing, replay and external effects

Pin the complete durable work identity, scope, generation/version, owner and lease. Verify the active fence inside the transaction that commits a transition; checks only before claim or before an external call leave a race. Define deadline and time source, including whether expiry at the exact boundary invalidates the lease. If an external call can outlive a lease, size the lease against its enforced timeout and completion margin or use a proven fenced renewal protocol; typical latency is not a bound.

When an atomic checkpoint advances the active state version while a journal retains an immutable original start fence, carry and verify both identities explicitly. Do not reconstruct an old journal fence as a fixed subtraction from the current version: intervening checkpoints and claims can advance it differently. Equality with a saved expiry is not proof the lease is still live; check the authoritative clock as required by the contract.

A schedule lease and a lock on a shared external subsystem may protect different resources; inventory both before asserting single-flight. For recurrent operator transitions, bind each decision to the actual immutable run and current locked state, test a later cycle as well as bootstrap, and do not infer completed recurrence from one observed run. If a database owns deadline authority, evaluate it at the actual decision/commit boundary rather than assuming a previously read application timestamp remains current.

Install the durable terminal result and ordered effect journal atomically when the contract requires both. Only the winning fenced transition may dispatch effects. Record each step and resume only the uncheckpointed steps after a restart. An external effect can complete while its response or local checkpoint fails: use an idempotency key accepted by the actual external system where supported, or retain an explicit ambiguous state and reconcile instead of silently repeating it. Do not promise exactly-once behavior beyond the proven provider and storage boundaries.

On a replay, check current caller authority, work identity and original payload semantics before returning a recorded result. Test exact replay, mismatched payload, foreign scope, stale/expired lease, duplicate dispatch, competing claim and restart. Assert rejected paths leave durable rows, artifacts and external effect counts unchanged.

Operator reconciliation must bind an approved exact snapshot, observable external evidence and identity, then revalidate under the newly acquired fence before changing state. Preserve the breaker, run count and one-shot semantics. Do not turn uncertain expiry into an automatic retry, treat a successful claim alone as proof, or invoke the executor as a side effect of a read-only inspection.

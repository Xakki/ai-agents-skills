# Artifact, recovery and cross-consumer evidence

For generated code or structured artifacts, inspect the producer, generated bytes and real consumer. Test syntax and behavior using bounded offline fixtures; enforce size and cardinality before costly materialization and again at the receiving boundary where required. Fixed key names do not make arbitrary values safe to log. Source-text checks alone do not prove execution order or absence of side effects.

For credentialed recovery, trace archive acquisition, runtime/container boundary, credential handoff, actual importer and cleanup. A no-follow check inside a container does not by itself prove the host resolved the mount without following links. Test valid and invalid synthetic credentials, replacement after acquisition, simultaneous attempts, partial failure and supported interruption; never claim normal exit traps cover hard kill or host loss. Confirm the wrapper uses the validated object rather than reopening an uncontrolled pathname.

For configuration and observability, identify every consumer's actual secret representation, route and logging contract. A file format accepted by one consumer may be invalid for another. Check locally generated configuration without revealing resolved secrets and distinguish best-effort writes, durable storage and end-to-end delivery. Static configuration tests do not establish external ingress or scrape behavior.

Keep exact candidate identity, current test outcomes, not-run gates and independently unverified claims in the verdict. A separate test harness or verifier can establish its observed seam; it is not automatically a live deployment test or independent human review.

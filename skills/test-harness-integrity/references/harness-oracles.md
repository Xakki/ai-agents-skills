# Harness oracle credibility

Trace the actual producer through final serialization, selection and the deciding assertion. If a fake replaces an external tool, make it parse the actual arguments and model both owned and unrelated resources in the same observable inventory. A fake that always returns expected data can make an invalid selector look safe. Keep expected-error assertions outside the catch that accepts the production error so that a failed test assertion cannot satisfy its own oracle.

For result-processing gates, exercise the real report producer and consume its finalized artifact through the actual decision predicate. A fabricated artifact proves the consumer but not that upstream phases emit and preserve the properties it relies on. Exercise relevant failure, skipped or expected-failure cases as well as an ordinary passing control, according to the gate's contract.

When a test makes timing or streaming claims, include the work defined by the contract in the measurement and prove the oracle detects a controlled overrun. A buffered fake may bypass stream consumption and cleanup; observe physical closure and finalization when those are claimed.

Check independently selected negative cases and valid controls: each claimed guard must reach its deciding boundary rather than failing an earlier unrelated guard. Verify a known positive detection when asserting absence. Preserve real process, protocol, test and cleanup outcomes separately, including incomplete or missing artifacts.

Use disposable authorized fixtures and synthetic data. Report distinct evidence scopes for fixture behavior, the actual toolchain and independent acceptance; do not upgrade one into another. Security, access and approval refusals remain binding.

# Privacy and no-read evidence

Build one row per source, derived value, allowed destination and forbidden boundary. Exercise the real available application flow for persistence, HTTP, logging and telemetry independently. A response body check does not inspect headers; a passing database test does not prove a storage bucket or a logging exporter is private. Verify private object paths against the actual policy and known synthetic objects where authorized, including a valid public-object control if public access must remain functional.

For redaction, test nested key-context as well as marker strings, values inside opaque extension structures and applicable URL/header/cookie representations. Verify ordering before public serialization, public fingerprints, hooks and persistence, including replay/conflict paths; preserve distinctions required by the contract. If secret differences are part of request identity, redacted inputs alone cannot detect those conflicts. Where policy allows, a protected keyed fingerprint over the canonical original request can preserve that distinction; define secure key custody, rotation and replay retention, and never emit the payload, key or digest in public output or logs. Sanitizer failure must not leak raw content. Use contract-valid positive controls and avoid printing actual test or production secrets.

When truncation is part of a sanitized durable outcome, redact the complete sensitive value before applying its output limit. Truncating first can remove the delimiter needed to recognize a credential. Verify every intended durable and audit sink rather than only the displayed or in-memory representation.

For a no-body-read requirement, admit command control files and scoped paths before execution: commands that print only names may still read working content. Calibrate any read observer on a dummy positive control and cover the actual process tree, readable mappings, parser behavior and unknown attribution. A silent or incompletely covered trace is not proof of zero reads. Metadata stability is not a body-byte comparison; hashing an excluded body would itself violate no-read.

Capture configured logging through the actual available wiring when claiming it is safe. A synthetic or injected test handler may establish a service-level seam but does not establish production handler delivery. If no record or handler can be observed, label that surface unavailable rather than inventing evidence. Report each verified and unverified boundary separately, preserving any partial valid result and native failure.

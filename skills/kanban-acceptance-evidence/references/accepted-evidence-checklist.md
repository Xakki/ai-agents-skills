# Accepted evidence checklist

- Locate the live repository and canonical card; capture branch, HEAD, index, unrelated state, original bytes, owner and filesystem mode. Git blob mode does not determine exact POSIX permissions. Preserve observed permissions; do not broaden them based on an unverified assumption.
- Read the full card and actual final reviewer artifacts, validate identifiers, and verify the reviewed candidate, source/configuration pins, protected inputs, and allowed closure paths. A documentary exception does not exempt a protected input from baseline verification. Preserve review snapshots and report corrections separately.
- Append only the authorized dated, sanitized evidence: verdict, reviewed revision or chain, exact checks and results, coverage, limitations, relevant contracts and runtime/cache/generated-state facts. Use exact observed names and never invent identifiers, counts or observations. Deduplicate coverage across reviews by the union of paths and cases, not summed counts.
- Record each review iteration and observed route; keep effective reasoning and fallback unknown unless observed. Reuse unaffected prior evidence only when its source and configuration bindings still match, and label it historical. Name the remaining owner and missing evidence; distinguish preparation, installation, privileged admission and live proof.
- Verify the original-length prefix against the frozen digest, unchanged protected pins, complete authorized diff, and whitespace. A clean diff or successful patch alone cannot prove original history was preserved.
- Run the sanctioned card linter. Verify actual selector and nonzero checked count; report targeted and aggregate scopes accurately, including diagnostics and exit. Inventory collisions and excluded historical stages require separate checks. If the card later moves to an excluded stage, label pre-move evidence historical and any isolated copy-based rerun as such.
- Without authorization, leave the index unchanged. For an authorized card-only commit, stage the final card body, inspect cached paths and complete diff including any rename, and follow the repository message policy. Verify exit, SHA, parent, exact committed paths and content, preserved history, post-commit checks and unrelated state.
- State explicitly what remains outside scope: successor work, `done`, merge, push, release, deploy or data deletion need their own authorization. Mark unrun checks NOT_RUN and never present carried tests as newly executed.

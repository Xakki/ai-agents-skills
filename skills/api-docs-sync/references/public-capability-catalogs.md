# Public capability catalog reconciliation

Use for a public API index, `llms.txt`, sitemap-facing catalog or similar listing. Establish authorized scope and inspect canonical implementation pages, endpoint handlers, specifications, localized equivalents and project manifests before correcting claims.

- Reconcile category and total counts, localized entries, endpoint names and request shapes across affected catalog surfaces.
- Document the actual authentication, rate limits, pagination, freshness, data source and protocol boundaries. Do not overstate completeness, authority or live data; an indexed dataset is not necessarily a live feed. Different protocols or endpoint families must remain distinguishable.
- Remove a negative claim only when evidence proves it stale, replacing it with accurate limits. Preserve valid negative boundaries.
- Run the narrowest supported static or consistency gate. Where no docs checker exists, consider deterministic assertions for required entries and forbidden stale claims. Respect constraints on containers, networks and other resources; distinguish a dry run from execution.
- Inspect the full staged set before any authorized commit and preserve unrelated changes. Record secret-free evidence and actual outcomes; do not change task or board state without authorization.

The former supplementary catalog examples were unavailable in the source skill; this checklist does not claim to restore them.

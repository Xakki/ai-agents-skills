# Delivery safeguards

Capture pre-existing state and do not reset, restore or stash unrelated paths. Treat secret-bearing files as opaque. When loss is observed, stop and disclose it; preserve evidence and do not fabricate restored content.

Separate normative acceptance from historical rationale. Trace public API claims through actual source, persistence, serializer and documentation; a persistence requirement does not by itself require a new public field. Verify claims about a dependency against its installed or pinned version. Source inspection is not proof of runtime behavior; exercise the appropriate authorized seam and preserve native receipts.

For generated public contracts, identify the authoritative model and its consumers, retain surrounding registration/frontmatter, generate deterministic marked content, and check freshness and idempotence through the supported project runner. Test both missing and obsolete entries with causal negative controls.

For structural security guards, define source coverage and intentional exclusions, ensure production assertions and synthetic fixtures use the same rejecting validator, and test both valid controls and well-formed ungated mutations. Trace caller-to-enforcement chains; structural checks alone do not prove runtime authorization, ordering or correct arguments.

For temporary artifact boundaries, inventory indirect consumers, define actor/operation/state coverage and isolate test-owned resources. Pair denials with a valid owner control and verify unchanged state. Calibrate the test oracle to the actual contract and report only the exercised lifecycle and paths; an abandoned-object cleanup test is not proof of successful-completion cleanup.

Keep implementer and independent review distinct when required. Preserve partial changes and receipts after a worker limit; commit or revert only within authorization. External notification requires its own explicit authorization.

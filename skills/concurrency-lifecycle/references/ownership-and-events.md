# Ownership and event handoffs

Define the transition, resource identity, old and new owner, fencing generation and effect boundary. Replacement and generation assignment must be atomic under the actual synchronization model; stale teardown can release only the ownership it still holds. Revocation blocks authority, while actual quiescence may require separate task, transport, process and descendant settlement. Do not release a shared reservation solely because a logical close was requested.

Use deterministic barriers at production transition points and bound every wait. Hold old teardown or publication, attempt competing admission and stale finalization, then release and verify the accepted result, durable state and effects. Assert that rejected stale work produces no row, artifact or external effect delta. A received-but-not-yet-published frame is distinct from bytes purportedly arriving after the transport closed; the fixture must respect actual transport behavior. Test the old result handler and real owner lifecycle, not only a token helper.

For a claimed row-lock timing leak, independently establish real contention with the database's supported probe, use an authenticated allowed positive control and an absent-resource baseline, and measure the actual handler under the same bounded hold. A slow baseline or missing contention control makes the result inconclusive; one bounded test does not establish constant-time behavior or all side-channel resistance.

For uncorrelated request/reply transports, protect the whole send-and-receive exchange. A timeout or invalid reply after I/O may leave an ambiguous late reply; do not reuse or drain the capability without a supported, tested correlation and recovery protocol. Invalid input rejected before I/O should not unnecessarily retire an otherwise healthy capability. Preserve exact caller/subject association and test both allowed and veto controls.

When an action captures one matching event, define the dispatcher’s real completion/settlement semantics. A bounded quiet window can detect duplicates within that window, but does not prove that no later event is possible. Model task-scheduled callbacks rather than an inline-only fake; route callback errors to the owner, remove or fence the handler, and test late callbacks for unhandled exceptions. Metadata-only adapters must not access unapproved bodies, credentials or lifecycle methods.

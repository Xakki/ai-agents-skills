# Plan

Use when the user requests a plan or the active workflow requires planning before implementation. Establish the desired outcome, actual project, authorized scope, relevant constraints and current state. Research the code and interfaces needed for a concrete decision; distinguish known facts from assumptions and unresolved questions. A plan-only instruction is not permission to implement.

Describe the proposed approach, affected areas, ordered work, applicable checks, dependencies and material tradeoffs. Prefer the minimum detail needed to make the decisions reviewable. Preserve prior approved decisions and user exclusions. Ask only for choices that materially affect the plan, grouping independent questions where appropriate.

If a durable plan is requested, save it to the location selected by the user, project or supported runtime; do not invent an agent-specific home path. State what has and has not been performed. Once implementation is authorized, use the plan as guidance while adapting to evidence and preserving the agreed scope.

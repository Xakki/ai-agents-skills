# Cross-layer boundary evidence

Inventory producer, transport, adapter, validation, state transition, persistence, audit, output and runtime composition. For each structured field or status, compare actual producer values with consumer-accepted values, including success, failure, rollback, unknown and documented sentinels. Trace new optional metadata through both direct delivery and durable write/read/reconstruction; a live envelope can hide loss during recovery.

Exercise the real adapter boundary and approved positive and negative cases. A parser test alone does not prove persistence, authorization, worker dispatch or redaction; a mock must not erase the boundary under examination. Check validation order when refusal must precede quota, writes or external actions. Verify actual runner scope and count the tests that ran; a supplied filter is not proof the runner honored it.

For architectural boundaries, use the project's actual import/port/DI policy and explicit exceptions. Test the meaningful behavior and resolve each required port through the configured container where applicable; declaration or self-equality alone does not prove a binding. Keep historical measurements distinct from the current source inventory.

For asynchronous user actions, distinguish submission, durable record, artifact bytes, processing and terminal result; a success toast or transport status is not completion. If an attempt is ambiguous, reconcile the owned state before any separately authorized retry. For shipped assets, separately prove image contents, delivered bytes, browser execution and observed external requests as required. Do not turn a build without one download into a claim of a fully offline build.

Independent review remains read-only. Report concrete trigger, source location, violated invariant and observed consequence for findings, and classify unavailable tests or external dependencies as limitations. Separate source readiness from migration, deployment and runtime proof.

For performance acceptance, predeclare control and candidate, trial counts, isolation, workload and sampling interval. Capture the entire relevant window and retain raw samples, readiness and shutdown timing. Reject incomplete or invalid trials; independently recompute the required statistic and worst observed peak. A post-start sample or green functional test does not prove a startup peak or improvement. Describe fixture scope separately from production behavior.

For telemetry, follow each required signal from producer through receiver and storage to a queryable read-back; a listening port or accepted export does not establish delivery. Bound metric dimensions and avoid placing account-specific identifiers in labels unless explicitly required. For stream outcomes, distinguish completion, application error, transport error and cancellation using the real protocol, and prove instrumentation does not alter the response.

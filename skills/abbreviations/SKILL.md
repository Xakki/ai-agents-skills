# abbreviations — словарь сокращений для именования

**Инвариант:** единственный источник правды по общепринятым сокращениям для
имён (переменные / функции / классы / CSS-классы / токены) и для сжатого
технического текста. Растущий, пополняемый словарь — не дублировать его в
других местах (project `CLAUDE.md` держит только policy + компактное
ядро + указатель сюда, см. ниже).

## Policy (почему это важно)

- **Сокращения — только общепринятые, по максимуму.** Не изобретай свои —
  используй те, что узнаются с первого взгляда любым разработчиком (см.
  [dictionary.md](dictionary.md)). Приватный/проектный жаргон в этот
  словарь не идёт — он общий для всех проектов.
- **Имена говорят сами.** Переменная / функция / класс / CSS-класс / токен
  должны быть понятны по одному имени. Если тебе приходится комментировать,
  что означает имя — переименуй его вместо того, чтобы объяснять.
- **Комментарии — минимум.** Объясняй «почему», а не «что»; хорошее имя не
  нуждается в пояснении «что».

## Happy-path: как применять

1. Называешь переменную/функцию/класс/CSS-класс/токен или пишешь сжатый
   технический текст (комментарий, коммит-сообщение, лог) → сначала проверь
   [dictionary.md](dictionary.md) — есть ли уже принятое сокращение для этого
   понятия.
2. Нашёл подходящее → используй его как есть (форма/регистр из словаря).
3. Сокращение неоднозначно в данном контексте (см. пометки о неоднозначности
   у `acc`, `res`, `tx` и т.п. в словаре) → выбери disambiguation по правилу
   словаря (обычно — более длинное явное имя или уточняющий префикс), не
   гадай.
4. Нужного сокращения в словаре нет, но оно **действительно общепринято**
   в мейнстримной разработке (узнаётся с первого взгляда, не единично для
   одного стека/компании) → можно его использовать, и затем выполни шаг
   пополнения ниже. Если сокращение сомнительное/локальное — пиши слово
   полностью.

## Expansion process (пополнение словаря)

- Встретил или ввёл новое общепринятое сокращение, которого нет в
  [dictionary.md](dictionary.md) → **допиши туда строку**: `сокращение |
  полная форма | контекст` — в подходящий тематический раздел (или заведи
  новый, если ни один не подходит).
- Это **единственное** место для пополнения — не создавай отдельных таблиц
  сокращений в других skill'ах или project `CLAUDE.md`. Проектные
  `CLAUDE.md` держат только policy-абзац + компактное ядро (~10-15 самых
  частых строк) + указатель на этот skill; полный растущий список живёт
  только здесь.
- Добавляй только сокращения, узнаваемые «с первого взгляда» в мейнстримной
  software-инженерии — никакого приватного/проектного/компанейского жаргона
  и никаких персональных данных (это общий плагин для всех проектов).
